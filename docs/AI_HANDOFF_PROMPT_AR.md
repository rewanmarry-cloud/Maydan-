# رسالة تسليم مشروع MAYDAN إلى ChatGPT المرتبط بحساب GitHub الصحيح

أنت المساعد المسؤول عن استكمال مشروع MAYDAN. اقرأ `MAYDAN_MASTER_SPEC_AR.md` وجميع ملفات `docs/` و`AGENTS.md` قبل أي عمل. هذه الوثائق هي المرجع الأساسي للمتطلبات والتاريخ، لكن يجب مطابقة سجل الماضي مع المستودع الفعلي وعدم افتراض أن كل ما ورد ما زال موجوداً.

## 1. سياق صاحب المشروع
أنا صاحب MAYDAN وأستخدم هاتف Android فقط، ولا أملك حاسوباً. أعمل من خلال GitHub وCodespaces في متصفح الهاتف. أعطني خطوات عملية واضحة تناسب الهاتف، ولا تطلب مني تنفيذ كمية كبيرة من الأوامر دفعة واحدة. لا تدّعِ أنك نفذت أمراً أو اختبرت شيئاً ما لم تظهر نتيجة فعلية.

أنشأت حساب GitHub جديداً ببريد إلكتروني مختلف عن البريد الذي أستخدمه في ChatGPT. اختلاف البريد لا يمنع الربط؛ المهم أن يكون GitHub Connector داخل حساب ChatGPT هذا مفوضاً إلى حساب GitHub الذي يملك مستودع MAYDAN. في تجربة سابقة ظهرت واجهة GitHub داخل ChatGPT مع أمثلة مهام مثل شرح المصادقة ومراجعة Pull Request وتلخيص آخر سبعة أيام، لكن ظهور الواجهة لا يثبت وحده أن المستودع الصحيح متاح. كما أن استعلام قائمة المستودعات من حساب ChatGPT آخر أعاد قائمة فارغة. لا تفترض نجاح الاتصال قبل فحصه.

## 2. المطلوب منك أولاً — قراءة فقط
1. تحقق من المستودعات التي يستطيع اتصال GitHub الحالي الوصول إليها.
2. ابحث عن المستودع `Maydan` واعرض اسم المالك والرابط والفرع الافتراضي. لا تخمن اسم المالك.
3. إذا لم يظهر، توقف واشرح أن الحساب المفوض أو اختيار المستودعات يحتاج تصحيحاً. لا تنشئ مستودعاً جديداً ولا تطلب مني PAT في أول خطوة.
4. إذا ظهر، اقرأ `README.md` و`MAYDAN_MASTER_SPEC_AR.md` و`AGENTS.md` وجميع ملفات `docs/`، ثم افحص بنية المشروع الفعلية.
5. قدم تقرير تدقيق: ما الموجود، وما الناقص، وما المكسور، وما لا يمكن تأكيده.
6. لا تنشئ فرعاً ولا commit ولا PR ولا تعدّل أي ملف قبل التقرير وخطة قصيرة وموافقتي.

## 3. ما نريده في التطبيق
نريد تطبيقاً احترافياً أنيقاً وسريعاً وسلساً، Android أولاً باستخدام Flutter، بواجهة متجاوبة لا تقص النصوص والأزرار ولا تسمح بتمرير أفقي غير مقصود. يجب أن تدعم العربية RTL والفرنسية والإنجليزية LTR، مع خطوط مناسبة، تصميم متسق، ومناطق لمس واضحة.

اللغات: `ar`, `fr`, `en`.
- عند أول تشغيل، اتبع لغة نظام الهاتف إذا كانت مدعومة.
- إذا كانت لغة الجهاز غير مدعومة، استخدم الإنجليزية كخيار احتياطي.
- وفر إعداداً: استخدام لغة الجهاز / العربية / Français / English.
- احفظ الاختيار اليدوي حتى بعد إغلاق التطبيق.
- اختيار «استخدام لغة الجهاز» يعيد التطبيق إلى اتباع النظام.
- لا تفرض العربية على الجميع أو على كل الاختبارات.
- اعرض الأرقام الغربية `0-9` في اللغات الثلاث، واختبر التواريخ والعملات وحقول الإدخال.
- اسم Launcher بالعربية «ميدان»، وبالفرنسية والإنجليزية `Maydan`. ادرس موارد Android والـlocaleConfig وقيود اسم Launcher؛ لا تعد بتبديله حسب اللغة الداخلية إلا إذا كان ذلك مدعوماً ومختبراً.

التنقل:
- Dialog وBottom Sheet وDrawer يغلق أولاً عند الرجوع.
- الرجوع من صفحة فرعية يعيد إلى مصدرها الفعلي.
- الأقسام تحترم سجل التنقل ولا تقفز عشوائياً للرئيسية.
- لا تكرار للصفحات ولا فقدان غير مبرر لحالة الصفحة أو النموذج.
- الرجوع من الرئيسية يعرض تأكيد خروج.
- زر الرجوع داخل التطبيق متسق مع زر/إيماءة Android.
- قيّم مكدسات تنقل مستقلة للأقسام الرئيسية إن كان ذلك مناسباً.

الجودة:
- بنية كود واضحة وقابلة للصيانة.
- اختبارات ar/fr/en منفصلة.
- اختبارات التنقل تستخدم Keys أو Semantics identifiers، لا نصوصاً مترجمة ثابتة.
- اختبارات حفظ اللغة، الأرقام الغربية، الرجوع، الأسطح المنبثقة.
- GitHub Actions ينتج APK حقيقياً قابلاً للتنزيل والتثبيت.
- لا إعلان عن جاهزية APK قبل اختبار المستخدم له على هاتف فعلي.

## 4. الأخطاء السابقة التي يجب عدم تكرارها
المستودع القديم المعروف: `abdatimed28-dot/Maydan-`، وكان فرع سابق `feature/maydan-redesign-localization`. Commit معروف: `91d3a722955e70d124398f983138dd5b26c8f01e` برسالة `Complete MAYDAN localization and responsive verification`.

تغييرات غير ملتزم بها كانت في:
- `lib/core/localization/app_strings.dart`
- `lib/features/projects/field_operations_page.dart`
- `lib/features/projects/projects_page.dart`
- `lib/features/shell/app_shell.dart`
- `test/localization_navigation_test.dart` (ملف غير متعقب)

كانت توجد ملفات patch مؤقتة داخل `/tmp` في Codespace قديم، وقد تكون اختفت. لا تعتمد عليها قبل التحقق. بيئة قديمة أظهرت Flutter 3.47.9 وDart 3.13.7، لكن افحص البيئة الجديدة. نجح `flutter pub get` مرة، وفحص `dart format` خمسة ملفات دون تعديل، ولم تتوفر نتيجة نهائية مؤكدة لـ`flutter analyze`.

ظهر 67 اختباراً ناجحاً وثلاثة فاشلة:
1. `system Back closes modal surfaces before leaving the section`
2. `root system Back asks before exiting`
3. `system Back returns from a section and avoids duplicate history`

في اثنين لم يجد الاختبار نصاً عربياً مثل `أغلق السجل`، وظهرت `Found 0 widgets with text`. سجل الثالث لم يكن كاملاً. لا يوجد دليل أن الفشل كله بسبب اللغة. استخرج logs كاملة وشغّل كل اختبار منفرداً. لا تفرض العربية على الجميع، ولا تجعل اختبارات التنقل تعتمد على النصوص. لا تعدّل `app_shell.dart` لمجرد فشل Finder في العثور على النص. لا تحذف الاختبارات أو تخففها من أجل نتيجة خضراء.

ظهر مقتطف PopScope سابق يعتمد `scaffoldKey.currentState?.isDrawerOpen` في `canPop`، لكنه ليس حلاً مثبتاً. افحص lifecycle وسلوك Drawer وDialog وBottom Sheet وإصدار Flutter قبل أي إصلاح.

إذا كانت وصلة GitHub للقراءة فقط، فقل ذلك بوضوح ولا تدّعِ القدرة على دفع commits. استخدم Codespaces للتنفيذ الفعلي، وأرشدني خطوة بخطوة. لا تدمج أي تغيير إلى `main` قبل موافقتي.
